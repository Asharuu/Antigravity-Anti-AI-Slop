## English

> **Say Goodbye to AI Slop.**  
> Strict guidelines to ensure all user interfaces, program code, architecture, and copywriting generated by AI feel **authentically human-crafted**, functionally grounded, and free from standard LLM vices.

---

### 📌 What is "AI Slop"? (The Problem)

When modern AI coding assistants generate frontend views, codebases, or architectures, they frequently fall victim to bad habits known as **AI Slop**:
1. **Technical Plumbing Leaking into UI**: Exposing internal database table names, socket ports, or backend status codes in public user-facing screens.
2. **Non-Functional Visual Gimmicks**: Inserting high-distraction marquee tickers on login/checkout pages, forcing cyberpunk neon gradients on serious business apps, and scattering gratuitous emojis (`🚀✨⚡`).
3. **Over-Engineered Code**: Introducing 5 layers of premature abstraction (*Factory, Strategy, Repository, Adapter, Facade*) for a trivial CRUD operation.
4. **Awkward Layouts & Typographic Yelling**: Setting every heading and button in `BOLD ALL-CAPS` alongside unbalanced grid layouts with isolated "orphan" cards.

This skill equips Google Antigravity with genuine human design intuition and engineering restraint.

---

### 🏛️ The 4 Pillars of Anti-AI Slop

#### 1. 🎨 UI/UX & Layout Discipline
* **Contextual Appropriateness**: Design for the real world. Operational tools (retail POS, warehouse ERP, inventory portals, analytics dashboards) require assertive contrast, accessible buttons, and low distraction—not indie concert posters or dark cyberpunk themes.
* **Balanced Human Layout**: Avoid awkward layout orphans (e.g., 4 cards on row one, followed by 1 isolated card on row two). Build balanced responsive grids (e.g., modular 2-4 column or 3-3 layouts).
* **Generous White Space**: Provide ample padding and margins. Overcrowded interfaces quickly cause user fatigue.
* **Typographic Restraint**: Never format every title and button in `BOLD ALL-CAPS`. Use natural typographic hierarchies (*Title Case* for headings, *Sentence Case* for descriptive labels).

---

#### 2. ✍️ Interface Copywriting Discipline

| Context | ❌ Bad (Technical AI Slop) | ✅ Good (Human-Crafted) |
|---|---|---|
| **Login Screen** | *"PostgreSQL Pool active · JWT HS256 auth verified"* | *"Sign in to Management Portal"* / *"Enter your email and password to begin"* |
| **Stock Alert** | *"Executing: SELECT * FROM items WHERE stock < 5"* | *"5 items are running low on stock and need reordering."* |
| **Demo Account Picker** | *"Quick demo accounts loaded from seeds/01_users.sql"* | *"Select Demo Role Profile"* |
| **Marketing Headline** | *"Leveraging next-gen AI synergy to empower productivity"* | *"Fast and intuitive inventory management for growing teams"* |

* **Zero Gimmick Clutter**: Never place marquee tickers on high-focus workflows (Login, Checkout, Forms).
* **Stop Emoji Spam**: Avoid sprinkling `✱`, `❋`, `⚡`, `◆`, `🚀` on every headline and button.

---

#### 3. 💻 Code Quality & Architecture Discipline
* **Anti Over-Engineering**: Adhere to **KISS** (*Keep It Simple, Stupid*) and **YAGNI** (*You Aren't Gonna Need It*). Avoid bloated architectural layers for straightforward endpoints.
* **Eliminate Echo Comments**:
  ```typescript
  // ❌ AI Slop: Lazy redundant comments restating obvious code
  // Function to calculate invoice total
  function calculateTotal(items: Item[]): number {
    return items.reduce((sum, item) => sum + item.price, 0); // Return total sum
  }

  // ✅ Clean: Code is self-explanatory; comments explain non-obvious business reasons
  function calculateTotal(items: Item[]): number {
    return items.reduce((sum, item) => sum + item.price, 0);
  }
  ```
* **Lean Dependencies**: Favor modern native Web APIs and platform features over importing heavy third-party packages for trivial single-line tasks.

---

#### 4. 📝 Git Commits & Documentation Discipline
* **Clean Conventional Commits**: Write concise conventional commits (`feat: ...`, `fix: ...`) that state changes directly without robotic filler.
* **Pragmatic Documentation**: Focus immediately on prerequisites, environment flags, and setup commands without generic conversational preambles.

## Bahasa Indonesia

> **Say Goodbye to AI Slop.**  
> Pedoman ketat (*strict guidelines*) untuk memastikan seluruh antarmuka web, kode program, arsitektur, dan *copywriting* yang dihasilkan AI terasa **orisinal, fungsional, dan dirancang oleh manusia profesional (*human-crafted*)**.

---

### 📌 Apa itu "AI Slop"? (The Problem)

Seringkali ketika coding assistant / LLM diminta membuat tampilan web, menulis kode, atau merancang arsitektur, AI memunculkan kebiasaan buruk yang disebut **AI Slop**:
1. **Kebocoran Plumbing Teknis ke UI**: Membocorkan nama tabel database, port koneksi, atau status internal backend ke teks publik yang dilihat pengguna.
2. **Gimmick Visual Tanpa Fungsi**: Memasang running ticker/marquee yang mengganggu konsentrasi, gradien neon cyberpunk di aplikasi kasir/ERP serius, dan taburan emoji berlebihan (`🚀✨⚡`).
3. **Over-Engineering Kode**: Membuat terlalu banyak layer abstraksi (*Factory, Repository, Strategy, Facade*) hanya untuk fungsi CRUD sepele.
4. **Typographic & Layout Canggung**: Menggunakan huruf kapital tebal (*ALL-CAPS*) di seluruh layar serta kartu grid yang terisolasi tanpa keseimbangan visual.

Skill ini menanamkan intuisi insinyur dan desainer manusia (*human engineering & design discipline*) ke dalam Google Antigravity.

---

### 🏛️ 4 Pilar Anti-AI Slop

#### 1. 🎨 Desain UI/UX & Tata Letak (Visual & Layout)
* **Kesesuaian Karakter & Konteks**: Rancang antarmuka sesuai dunia nyata. Aplikasi operasional (POS kasir, ERP gudang, dashboard analitik) memerlukan kontras tegas, tombol mudah diklik, dan minim distraksi—bukan estetika poster musik atau tema gelap cyberpunk.
* **Keseimbangan Grid & Ritme Tata Letak**: Hindari layout canggung dengan kartu atau tombol "kesepian" (misal: 4 kolom di atas, lalu 1 elemen terisolasi di bawah). Gunakan grid modular yang seimbang (misal: responsif 2-4 kolom atau 3-3).
* **Ruang Bernapas (White Space)**: Berikan *padding* dan *margin* lapang. Antarmuka padat tanpa jeda cepat melelahkan mata pengguna.
* **Typographic Restraint**: Jangan membuat semua label menjadi `ALL-CAPS BOLD`. Gunakan skala tipografi yang proporsional (*Title Case* untuk judul, *Sentence Case* untuk deskripsi).

---

#### 2. ✍️ Teks & Antarmuka (Interface Copywriting)

| Konteks | ❌ Buruk (AI Slop Teknis) | ✅ Benar (Human-Crafted) |
|---|---|---|
| **Halaman Login** | *"PostgreSQL Pool active · JWT HS256 auth verified"* | *"Masuk ke Portal Manajemen"* / *"Masukkan email dan kata sandi Anda"* |
| **Pemberitahuan Stok** | *"Executing: SELECT * FROM items WHERE stock < 5"* | *"5 barang hampir habis dan memerlukan pemesanan ulang."* |
| **Pilihan Akun Demo** | *"Quick demo accounts loaded from seeds/01_users.sql"* | *"Pilihan Profil Uji Coba Peran"* |
| **Headline Promosi** | *"Leveraging next-gen AI synergy to empower productivity"* | *"Aplikasi manajemen inventaris yang cepat dan mudah digunakan"* |

* **Zero Gimmick Clutter**: Dilarang memasang running marquee di halaman login/checkout.
* **Stop Emoji Spam**: Hindari menaburkan `✱`, `❋`, `⚡`, `◆`, `🚀` di setiap tombol dan judul.

---

#### 3. 💻 Arsitektur & Kualitas Kode (Clean Code)
* **Anti Over-Engineering**: Terapkan prinsip **KISS** (*Keep It Simple, Stupid*) dan **YAGNI** (*You Aren't Gonna Need It*). Jangan membuat 5 lapis abstraksi untuk fungsi sederhana.
* **Hapus Komentar Gema (Echo Comments)**:
  ```typescript
  // ❌ AI Slop: Komentar malas yang mengulang kode
  // Function to calculate invoice total
  function calculateTotal(items: Item[]): number {
    return items.reduce((sum, item) => sum + item.price, 0); // Return total sum
  }

  // ✅ Clean: Kode sudah jelas, komentar hanya untuk alasan bisnis yang rumit
  function calculateTotal(items: Item[]): number {
    return items.reduce((sum, item) => sum + item.price, 0);
  }
  ```
* **Dependensi Ramping (Lean Dependencies)**: Gunakan fitur bawaan modern Web API daripada memasang library eksternal besar untuk keperluan sepele.

---

#### 4. 📝 Komunikasi & Dokumentasi (Git & Docs)
* **Commit Bersih & Ringkas**: Gunakan standar conventional commits (`feat: ...`, `fix: ...`) yang menjelaskan perubahan secara to-the-point tanpa pendahuluan robotik.
* **Dokumentasi Praktis**: Fokus langsung pada cara instalasi, konfigurasi environment, dan panduan penggunaan.
